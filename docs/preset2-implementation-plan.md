# 预设 2：悬浮卡片布局设计与实现方案

> 状态：方案稿（第三版），未修改运行时代码。  
> 基线：`@xiaopb/dsh-mobile-layout@0.2.11`，`lib/client.js` 单文件发布物。  
> 命名：设置项共三档 —— **原生**（`default`）/ **融合**（`classic`）/ **悬浮**（`v2`）。入口只有一处：设置 → 通用设置 → 外观下面的「布局模式」卡片。

## 0. 版本说明与已定决策

第一版按截图复刻，第二版改为功能驱动，本版落定六项决策：

| # | 决策 | 落点 |
|---|---|---|
| 1 | 底部导航五项：**会话 / 工作区 / 插件 / 工作台 / 设置**，工作台即 DSH 右侧面板 | 6.5 |
| 2 | 新建只在顶栏与抽屉 | 6.3、6.5 |
| 3 | 运行态进度条不单独探针，并入阶段 A 一次性抓取，读不到就删 | 6.3、8、9 |
| 4 | 首次安装默认 `classic` | 4.1、5.4 |
| 5 | 加号面板分「附件 + 能力」，能力分组直接读官方分组标题（添加 / 指令 / Skill 等），不自造分类 | 6.7 |
| 6 | 顶栏更多菜单完全沿用 DSH 自带项（下载会话日志、反馈等），只改样式 | 6.8 |


本版的设计基准换成三句话：

1. **借结构，不借皮**：只沿用参考图的骨架关系 —— 吸顶栏 + 主体 + 悬浮输入卡 + 底部导航 + 侧抽屉 + 贴底面板 + 锚定浮层。颜色、字体、图标、文案、动效节奏全部重新定。
2. **只放真实能力**：导航项、快捷入口、面板分组，每一项都要能落到 DSH 已有入口或本插件已有函数；没有数据源的槽位直接不渲染。
3. **高频优先**：按“每个会话 / 每几分钟 / 每个任务 / 偶尔”分层决定谁占底部、谁进抽屉、谁藏在浮层。

不新增业务能力，不复制手势、浮层栈、上传回流、键盘测量等通用实现。

## 1. DSH 实际能力盘点

下表是本插件当前真实可用的入口。预设 2 的所有设计都从这张表里选料，不再从截图里选料。

| 能力 | 真实入口 | 现状 | 频率 |
|---|---|---|---|
| 新建会话 | `startNewSession()` → `workspace.startSession()` | 预设 1 底栏第 1 键 | 高 |
| 会话列表 | `openSheet('sessions')`，数据 `sessions.list` + 工作区分组 | 预设 1 底栏第 2 键 | 高 |
| 切换会话 | `openSession(id)` | 会话表行点击 | 高 |
| 发送 / 附件上传 | 官方 composer；插件 `injectOfficialFiles()` 回流 | 预设 1 底栏文件、图片键 | 高 |
| 语音输入 | 官方 composer 语音键 | 未额外处理 | 中 |
| 权限切换 | 官方权限 chip，短文案 `完全访问 / 工作区 / 只读` | 由 `syncComposerChips` 打标 | 中 |
| 模型切换 | 官方模型 chip，`modelShort()` 压成 `V4.1 · H` | 同上 | 中 |
| 加号面板（能力） | `openOfficialAddMenu()`；官方 `role=listbox` 内已有 `role=presentation` 分组标题，`collectAddOptions` 会返回 `{ group, key }` | `tagComposerMenus` 打标 + 4×2 分页 | 中 |
| 侧栏 / 工作区树 | `requestDrawer(true)`，官方 sidebar（含插件、自动化、SSH 工作区） | 手势 + 吸附 | 中 |
| 工作台（右侧面板） | 官方 `[data-rightbar-col]`；插件已读 `data-rightbar-fullscreen` 并调用 `layout.closeRightbar()` | 仅手机全屏化，无常驻入口 | 中 |
| 插件面板 | `layout.selectPanel('plugins')` 或 `openSheet('plugins')` | 预设 1 底栏第 5 键 | 中 |
| 设置 | 官方设置对话框，`tagSettings` 全屏化 | 无插件配置项 | 低 |
| 顶栏更多 | 官方 `⋯`，实测项为**下载会话日志、反馈**等 DSH 自带项 | `tagComposerMenus` 定位 | 低 |
| 运行态 | 候选信号：发送键 aria-label 变化 / stop 按钮 / `[data-streaming]` | 未利用 | — |

频率分层结论：

- **T0（每个会话都要用）**：输入、发送、附件、权限、模型 → 全部留在输入卡内，不搬到别处。
- **T1（每几分钟）**：切换会话、新建会话 → 会话表 + 顶栏新建。
- **T2（每个任务）**：切换工作区、看工作台、插件、回到历史会话 → 底栏 + 抽屉 + 空态最近会话。
- **T3（偶尔）**：自动化、SSH、设置 → 抽屉与加号面板；设置因承载“布局模式”单独给一个底栏位。

预设 1 的底栏 6 键里，文件、图片、更多三项都是 T0 的重复入口（加号面板里已有），而 T1 的新建、会话只占两格。预设 2 的重新分配就是把 T0 收回输入卡，把 T1/T2 抬到底栏。

> 工作台的可达性有一个前提：手机宽度下官方是否仍暴露右侧面板入口（服务方法或顶栏按钮）尚需探针确认。若不可达，“工作台”一栏不渲染，降级为 4 键，绝不画一个点不动的按钮。

## 3. 设计原则

1. **功能密度优先**：一屏内优先放可操作的真实数据（会话标题、工作区名、时间、权限状态），不放装饰。
2. **不伪造数据**：没有数据源就隐藏，不用占位文案冒充功能。运行态读不到就不做进度指示，绝不画假的加载条。
3. **单色线稿 + 主题 token**：全部颜色走 `--dsw-alias-*`，深浅主题同一套规则，禁止写死白底。
4. **触控 44px 底线**：视觉可以 32/36，热区一律补到 44。
5. **动效只服务理解**：解释“从哪来、到哪去”，不做装饰性弹跳；减少动效时全部有位终态。
6. **通用能力零复制**：手势、吸附、浮层栈、键盘测量、上传回流、设置页全屏化全部复用现有实现。

## 4. 三档布局与设置项

### 4.1 三档定义

| 存储值 | 设置页名称 | 一句话说明 | 行为 |
|---|---|---|---|
| `default` | 默认（DSH 原生布局） | 保持官方布局 | 不启用插件手机外观，但设置页仍注入布局选择器 |
| `classic` | 融合 | 全宽底栏 + 融合输入区 | 当前仓库外观，交互不改 |
| `v2` | 悬浮 | 悬浮输入卡 + 五项导航 | 本方案新外观 |

首次安装与升级一律默认 `classic`（已定），避免行为突变；新用户可在设置里一键切到预设 2。

### 4.2 模式矩阵

| 宿主 / 形态 | 预设 | `data-dshm-mode` | 结果 |
|---|---|---|---|
| 桌面 | 任意 | `default` | 完全官方布局 |
| 手机竖屏 | `default` | `default` | 官方布局，仅注入布局选择器 |
| 手机竖屏 | `classic` | `mobile` | 预设 1 |
| 手机竖屏 | `v2` | `mobile` | 预设 2 |
| 横屏 / 平板 / 窄桌面 | 任意 | `default` | 官方布局 |

“默认”不等于卸载插件：模式探测、设置项注入、切回能力都保留。

### 4.3 持久化

- Key：`localStorage.dshm-layout-preset`，合法值 `default | classic | v2`。
- 非法值、读取异常、隐私模式拒绝写入：回退 `classic`，不写脏值。
- 监听 `storage` 事件做多窗口同步。
- 事件：`dshm:preset`（`{ preset, previous, version }`）；`dshm:mode` 语义不变。

## 5. 架构

### 5.1 三层拆分

```text
宿主 host      desktop / android / web
手机形态 phone  classify(width, height, previousPhone)  → 只回答“是不是手机竖屏”
外观预设 preset  default / classic / v2                  → 只回答“画哪套”
最终模式 mode   desktop 或 preset=default → default
               phone 且 preset=classic/v2 → mobile
```

拆层的唯一目的：`preset` 与 `mode` 解耦，切到“默认”后设置页仍在，用户能切回来。

### 5.2 DOM 契约

```html
<html data-dshm-form="phone" data-dshm-mode="mobile" data-dshm-preset="v2">
```

- `classic`：现有 CSS 全部照旧，只多一个 `data-dshm-preset="classic"`。
- `v2`：mobile 基础规则 + `[data-dshm-preset="v2"]` 覆盖段。
- `default`：不写 `data-dshm-mode`，保留 `data-dshm-form="phone"` 供设置项样式使用。

### 5.3 新增纯函数

```js
const PRESET_DEFAULT = 'default'
const PRESET_CLASSIC = 'classic'
const PRESET_V2 = 'v2'
const PRESET_KEY = 'dshm-layout-preset'

function resolvePreset(raw)                       // 白名单 + 回退 classic
function isPhoneForm(host, w, h, prev)            // 与外观无关的手机几何
function effectiveMode(host, phone, preset)       // 三层合成
function presetLabelKey(preset)                   // i18n key
function navSlots(caps)                           // 五项导航；caps 缺哪项就去掉哪项
function addPanelGroups(options)                  // 按官方 group 切段，空组丢弃
function composerState(draftLength, focused)      // collapsed / expanded
```

`addPanelGroups` 不做语义分类，只把 `collectAddOptions()` 已返回的 `group` 做**保序切段**：位置一律按官方顺序，插件只决定“这段用方块还是整行”——组内选项全部命中附件 key 时用方块，其余用整行；没有组标题时退化为单组，绝不臆造“专家/技能”这类官方未给的名字。

`navSlots(caps)` 的 `caps` 来自探针：`{ rightbar, plugins, settings }`。例如 `rightbar=false` 时返回四项，避免出现点不动的“工作台”。

### 5.4 状态

```js
{ phone: false, preset: 'classic', mode: 'default' }
```

`setPreset(next)`：规范化 → 持久化 → 写 `data-dshm-preset` → `evaluateNow()` → 进入/离开 mobile 时执行现有 `setMode()` 清理 → 派发 `dshm:preset` → 设置页下一帧重建选择器并恢复滚动。

### 5.5 代码改动地图

| 位置 | 改动 |
|---|---|
| `lib/client.js` 常量区 | 预设常量、存储 key、默认值 |
| `classify` / `resolveMode` 附近 | 新增 `isPhoneForm` / `effectiveMode`，原判定不动 |
| `state` / `setState` | 新增 `phone` / `preset` |

| `tagComposerMenus` / `syncAddPaging` | v2 跳过分页，改按官方 group 打段标记 |

| 测试 / 文档 | 新增 `test/preset.test.js`，更新 mode 测试与说明 |

### 6.3 顶栏

```text
┌──────────────────────────────────┐
│ ╭──╮  修复登录态丢失        ╭──╮ │
│ │☰ │  workspaces · 完全访问  │⋯ │ │
```

| 元素 | 规格 | 行为 |
|---|---|---|
| 菜单键 | 36 视觉 / 44 热区，圆角 10，`bg-layer-2` | `requestDrawer(true)`；不新增手势 |
| 标题 | 17/22，600，单行省略 | 官方会话标题；空态用“新任务” |
| 副标题 | 12，tertiary，单行省略 | **工作区名 + 权限短文案**（真实状态，非品牌话术） |
| 新建 | 36 圆 / 44 热区，主色浅底 | `startNewSession()`；空态与会话态都在 |
| 右侧工具 | 官方按钮统一 36 / 44，单行 | 原按钮全部保留，不收起、不隐藏 |
| 滚动后 | 背景加 12px 模糊 + 底边 hairline | 120ms |
| 运行态 | 底边 2px 不定进度（1.4s） | 见下：并入阶段 A 探测，读不到就不实现 |

运行态的处理（对应决策 3）：**不单独做一轮探针**。阶段 A 本来就要抓发送键与工具按钮，顺手记录三个候选信号即可，成本几乎为零：

1. 发送键 aria-label 从「发送」变为「停止生成 / 停止」；
2. composer 内出现独立的 stop 按钮；
3. 文档或 frame 上出现 `[data-streaming]` / `[aria-busy="true"]`。

任一可稳定读取 → 阶段 D 用 8 行代码加一个 `<html data-dshm-running>` 标记 + CSS 动画；三者都不可读 → 整个特性删除，不做替代动画。判断标准是“样本连续两次会话都能复现”，不能用猜测。

实现：

- 新增 `ensureV2Header(header)`：查找、打标、必要时补副标题节点，幂等。
- 副标题用插件节点或 `::after` 从 `data-dshm-v2-subtitle` 取值，不改官方标题文本。
- 降级：标题节点无法稳定定位时，只保留菜单键与右侧工具，不复制第二套 header。
- `data-dshm-v2-menu` 单独在 `verify-package` 放行，旧 `dshm-menu-btn` 继续禁止。

| 项 | 图标 | 行为 | 复用 |
|---|---|---|---|

| 工作台 | 右栏 | 打开官方右侧面板（`[data-rightbar-col]`） | 官方右栏 + 现有 `rightbarFullscreen` 全屏化 |
| 设置 | 滑杆 | 点官方设置入口，进入已手机化的设置页 | `tagSettings` |

工作台是这一版新增的唯一硬依赖，必须按“能力优先、不可达就不渲染”处理：

```js
function openRightbar(layout) {
  // 1) 官方服务方法（探针确认名称：openRightbar / toggleRightbar / showRightbar）
  for (const name of ['openRightbar', 'toggleRightbar', 'showRightbar']) {
    if (layout && typeof layout[name] === 'function') { layout[name](); return true }
  }
  // 1.5) selectPanel 若接受 'rightbar' 这类面板 id，也走同一路径（探针确认合法 id）
  // 2) 顶栏里已有的右栏开关按钮（按 aria-label / title 文本匹配）
  const toggle = findRightbarToggle()
  if (toggle) { toggle.click(); return true }
  // 3) 都不可用：返回 false，导航不渲染“工作台”
  return false
}
```

- 探测结果写入 `caps.rightbar`，由 `navSlots(caps)` 决定项数：`true` 五项，`false` 四项（会话 / 工作区 / 插件 / 设置），等分宽度自动重算。
- 右栏已全屏时，该项显示选中态；点击调用现有 `layout.closeRightbar()`（已在用），不自己改 `data-rightbar-fullscreen`。
- 右栏内部结构、关闭手势、遮罩全部沿用现有 `syncRightbarChrome` 与全屏规则。
- 若官方方法存在但手机宽度下不渲染右栏，仍按不可达处理，热区不保留。

设计取舍：

- **不放新建**（已定）：新建是动作不是目的地，只留在顶栏与抽屉首行，避免“点 tab 却没页面”的语义错位。
- **不放文件/图片**：官方加号面板已有，底栏再放一次是重复入口。
- **放插件**：插件面板是 DSH 的能力入口，和第二项工作区同属“上下文切换”，给固定位比藏在抽屉更好找。
- **放工作台**：右侧面板在桌面上是常驻区，手机上被折叠，补给一个固定入口能明显减少来回抽屉的操作。
- **放设置**：新增的“布局模式”开关在设置里，固定入口解决“切到默认后找不到回来路”的发现性问题。

规格：

- 高 56 + safe；背景 `bg-base`，顶部 hairline。
- 五项等分，每项 20%；图标 22，标签 11（`工作区/工作台` 三字在 320 宽下仍有 64px，不截断，实测不足时降到 10px）。
- 选中为主色 + 实心图标，未选中 tertiary；切换 160ms 颜色过渡，不做位移。
- 每项 44 热区；`aria-current="page"` / `aria-expanded` 正确切换。
- 输入法弹起、抽屉打开时整体淡出下移 8，不占位、不引起 reflow。
- 会话表打开时保留导航，方便连续切换会话。

**导航在三种「非首页」状态下的取舍（已定）**

| 状态 | 导航 | 实现 |
|---|---|---|
| 插件面板（`panelActive`） | **保留**，可继续换页 | `[data-slot="main"]` 底部让出 `--dshm-v2-nav`；`html[data-dshm-v2-page]` |
| 设置页（`data-dshm-settings-open`） | **保留**，可继续换页 | 覆盖预设 1 的 `[data-dshm-bottom]{display:none}`；设置弹窗 `bottom: var(--dshm-v2-nav)`；导航 `z-index: 1200` 压过弹窗的 1000 |
| 加号面板 / 模型 / 权限 / 工作区选择 | 留在原位，被覆盖式抽屉盖住 | 不给 `--dshm-panel-space` 预留（v2 恒为 0），导航不收缩 |

理由：手机应用靠底栏换页。插件和设置是「页面」，藏了底栏等于把人关在里面（预设 1 就有这个问题：进设置后只能靠 ✕ 退出）。而加号面板这类是「临时弹层」，本来就会被点走，不需要让位。

实现上还有一条必须处理的细节：设置页是 `z-index:1000` 的全屏 overlay，底栏被压在下面；且官方把底栏整行 `display:none`。所以 v2 要同时（a）恢复该行显示、（b）把设置弹窗底边收到导航上方、（c）把导航抬到 1000 以上。只抬 z-index 不够——行被 `display:none` 时导航本身就是 0×0。

切换到别的页面时必须先主动关掉设置页（`closeSettingsImmediate()`），否则新页面会被压在设置 overlay 下面，表现为「点了没反应」；再点一次「设置」则当作返回。

### 6.11 底部弹层形态（覆盖式抽屉）

加号面板、模型、权限、工作区选择这几类弹层，预设 1 的做法是「给 frame 预留等高底部内边距」，于是弹层出现时正文和输入卡被整体顶上去。预设 2 改成**覆盖式**：

| 项 | 预设 1 | 预设 2 |
|---|---|---|
| `--dshm-panel-space` | = 面板高度，撑起 `frame` 的 `padding-bottom` | 恒 `0px`（`syncPanelSpace` 按预设分流） |
| 正文 | 被顶起（reflow） | 不动 |
| 输入卡 / 导航 | 被抬到面板上方 | 留在原位，被面板盖住 |
| 面板外观 | 直角、顶部 1px 分隔线 | 上圆角 24、无分隔线、上投影，自底滑入 180ms |

- 官方弹层本身就是 `position: fixed; bottom: var(--dshm-safe-bottom)`，所以「不预留」天然得到贴底抽屉，不需要额外定位。
- 面板打开期间只给导航加 `pointer-events: none`，**不收缩高度**——收缩会让正文重新回流，等于又推了一次。
- 结论：弹层只在视觉上覆盖，任何情况下都不改变正文与输入卡的几何。

## 8. 动效

| 场景 | 属性 | 时长 | 曲线 | 说明 |
|---|---|---|---|---|
| 抽屉开合 | transform / 遮罩 opacity | 跟手，吸附 150–420ms | 现有曲线 | 完全复用，不改参数 |
| 输入卡展开 | 圆角、内边距、高度 | 200ms | ease-out | 高度用实测变量，不用 `auto` |

| 导航切换 | 颜色 / 图标填充 | 160ms | ease-out | 无位移 |
| 导航隐藏 | opacity + translateY(8) | 120ms | ease-in | 键盘 / 面板 / 设置 |
| 加号面板 | translateY(100%→0) + opacity | 220ms | ease-out | 遮罩 160ms |
| 顶栏菜单 | scale + translateY + fade | 140ms | ease-out | 右上锚点 |
| 会话表 | translateY + opacity | 240ms | ease-out | 现有 Sheet 动画 |
| 布局切换 | 内容层 opacity .82→1 | 160ms | linear | 不做整页快照 |

规则：

- 只动 `transform / opacity`，不动 `width / height`（输入卡除外，且用固定变量）。
- `prefers-reduced-motion: reduce` 下全部取消，保留终态。
- 不在 React 每次渲染重放入场；hero 入场改为 1 次 240ms 淡入或无。
- 不新增抽屉吸附算法、不改速度阈值。

## 9. 落地顺序

**阶段 A：DOM 探针（不改代码，一次抓齐）**

真机确认六组事实，一次记录、不反复开探针轮次：

1. **工作台**：`layout` 服务上是否有 `openRightbar / toggleRightbar / showRightbar`；顶栏是否有右栏开关按钮（aria-label / title）；手机宽度下右栏是否真的能展开。这决定导航是五项还是四项，优先级最高。
2. **顶栏**：会话标题节点、副标题可用数据（工作区名、权限短文案）、右侧工具按钮数量与 aria-label。
3. **输入卡**：语音 / 权限 / 模型 / 加号 / 发送的稳定 aria-label；设置页滚动容器与“外观”分组位置。
4. **加号面板**：`role=presentation` 组标题的实际文本与顺序、每个选项的「名称 / 别名 / 描述」三段、是否含拍照/相册/文件。
5. **更多菜单**：实际条目（已知含下载会话日志、反馈）、行高、是否含危险项。
6. **运行态**（顺手抓）：发送键 aria-label 是否切换、有无 stop 按钮、有无 `[data-streaming]` / `[aria-busy]`；连续两次会话复现才算通过。

产出：一页探针记录 + 选择器与降级顺序 + `caps` 取值。所有选择器必须有 `aria-label` 或文本兜底，不依赖哈希类名。

**阶段 B：预设基础设施**

预设常量、`resolvePreset`、持久化、三层拆分、设置页定位/装饰拆分与选择框。完成后即可验收“三档互切，切到默认还能切回”。

**阶段 C：预设 2 壳层**

顶栏、空态、悬浮输入卡、五项导航（含 `caps` 降级）、键盘联动、320/390/411 适配。

**阶段 D：浮层与视觉**

抽屉宽度与圆角、加号面板按官方分组渲染（含关闭重复项过滤）、更多菜单样式、会话表、设置页皮肤、动效与暗色；运行态进度条仅在阶段 A 通过时加入。

**阶段 E：测试与文档**

新增 `test/preset.test.js`；更新 `mode.test.js`、`verify-package.mjs`；更新 README / architecture / technical-notes / 截图；版本 `0.3.0`，bundle `VERSION` 同步。

## 10. 测试与验收

自动化：

- `resolvePreset`：三值、空、大小写、对象、异常。
- `effectiveMode`：桌面/手机 × 三预设全矩阵。
- `isPhoneForm`：滞回边界（600/640、1.25/1.15）。
- `navSlots`：`caps` 全开 5 项、`rightbar=false` 4 项且不含空位、键名无重复。
- `addPanelGroups`：单组、多组保序、附件组识别（alias 命中）、无组标题退化、空组丢弃。
- `composerState`：空草稿 + 失焦 = collapsed；有草稿或聚焦 = expanded。
- 源码契约：v2 样式仅存在于 `data-dshm-preset="v2"`；无 `dshm-menu-btn`；有 `data-dshm-v2-menu`；v2 不执行 `isDuplicateAddOption` 过滤；减动效段覆盖新增动画。

## 11. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 工作台无法从手机端打开 | 第 4 项变成死键 | 三级探测（服务方法 → 顶栏按钮 → 放弃）；不可达则不渲染该项，导航降为四项 |
| 官方顶栏 DOM 不稳定 | 标题/副标题错位 | 适配层幂等 + 兜底；缺失时只保留官方标题 |
| 加号面板分组标题为空 | 分组错落 | `addPanelGroups` 退化为单段整行列表，不补假组名 |
| 忘记关闭重复项过滤 | 「文件」入口消失 | v2 分支显式跳过 `isDuplicateAddOption`，单测断言「文件」仍可见 |
| 切到默认选择器消失 | 无法切回 | `phone` 与 `mode` 解耦，原生设置页继续注入 |
| 输入区压平标记残留 | v2 输入卡被拉平 | 同步函数按 preset 分支；切换时清旧标记 |
| 五项在 320 宽拥挤 | 标签截断 | 标签 11 → 10px；仍不足则只保留图标 + `aria-label`，不隐藏功能 |
| 运行态读不到 | 进度条不出现 | 直接不渲染，不做假动画 |
| 低端机掉帧 | 手感变差 | 只动 transform/opacity；不做错峰；减动效全关 |

## 13. 剩余待确认

六项主决策已定，仅剩两个由探针结果触发的分支，不需要现在拍板：

1. **工作台不可达时**：隐藏该键降为四项（本方案默认），还是把它改成“打开抽屉并定位到工作台/工作区区段”。前者更诚实，后者保留入口但语义偏移。
2. **附件组判定失败时**（官方组名与 alias 都不像附件）：整段按能力组渲染，还是保留 4 列宫格。默认前者，保证与预设 1 视觉差异一致。

两项都不改架构，可在阶段 A 结束后按实测数据一次性决定。
